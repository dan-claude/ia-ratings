Goal
- Build a web application that:
  0) Stores each film's Internet Archive description (when available) in the database and displays it above the embed player.
  1) Pulls all films in the Internet Archive collection "2026-public-domain-day-film-contest"
  2) Allows authenticated users to rate films across multiple criteria
  3) Supports an admin/judge mode with CSV export

Description field support (v1.1.18+)

- Server sync: Internet Archive advancedsearch requests `description` and stores it in `films.description`.
- Database: `films` table includes `description` (migration v3 adds it for existing DBs).
- API responses:
  - GET /api/films/next returns: identifier, title, description, embedUrl
  - GET /api/films/<identifier> returns: identifier, title, description, embedUrl
- Client: displays `film.description` above the embed viewer (iframe) when present.

Tech Stack
- Client: React + Vite
- Server: Flask (Blueprints)
- Database: SQLite
- Auth: Session-based

Clarification — films.metadata_json vs films.description

- Note: the column name is `metadata_json` (RECREATE previously used the shorthand `metadata`).

- `metadata_json` (JSON):
  - Raw Internet Archive item metadata captured at ingest time.
  - Stored as a JSON blob for lossless preservation, auditing, and future use.
  - Includes fields such as creators, subjects, collections, licenses, technical info,
    AND may include a `description` field as provided by Internet Archive.

- `description` (TEXT):
  - A normalized, first-class column extracted from Internet Archive metadata.
  - Used directly by the client UI and displayed above the embedded player.
  - Duplicated intentionally from `metadata_json.description` (when present) so the app
    can query, index, and display it without parsing JSON.

Design note:
- If Internet Archive provides a description, it is stored twice:
  1) verbatim inside `metadata` (lossless source of truth)
  2) normalized into `description` for application use

FILM DESCRIPTION CANONICAL BEHAVIOR

Ingestion (Internet Archive -> DB)
- Source field: Internet Archive item metadata key `description`.
- Types:
  - If IA `description` is a list/array: join elements with "\n\n" in order.
  - If IA `description` is non-string: cast to string via `str(value)`.
  - If missing/null: treat as empty string.
- Normalization:
  - Trim leading/trailing whitespace.
  - Preserve internal whitespace (do not collapse).
  - Treat content as plain text (do NOT render or sanitize HTML at ingest; store as received after trimming/joining).
- Storage:
  - `films.metadata_json` stores the raw IA metadata blob (JSON) as captured at ingest (lossless).
  - If `metadata_json.description` is present (non-empty after normalization), `films.description` MUST be populated with the normalized description text.
  - If `metadata_json.description` is absent/empty, `films.description` MUST be the empty string ("").

API contract (server -> client)
- `description` is ALWAYS present in film objects returned by the API.
  - If unknown/missing: return "" (empty string), not null.
- `metadata_json` is NOT required to be returned to the client UI; it may be omitted from list endpoints.
  - The UI must not rely on metadata_json for description.

Client rendering (Film panel)
- The film description is rendered ABOVE the embedded player inside the Film Panel.
- Rendering rules:
  - If `description` == "" after trimming: do not show the description block at all.
  - Otherwise show it as plain text with preserved newlines (\n renders as line breaks).
  - No HTML rendering (`dangerouslySetInnerHTML` must not be used).

Golden-path example (binding)
Input IA metadata excerpt:
{
  "identifier": "example_film_1923",
  "title": "Example Public Domain Film",
  "description": ["Line one.", "Line two."]
}

DB storage:
- metadata_json.description = ["Line one.", "Line two."] (raw JSON preserved)
- films.description          = "Line one.\n\nLine two."

API:
{
  "ia_identifier": "example_film_1923",
  "title": "Example Public Domain Film",
  "description": "Line one.\n\nLine two."
}

UI:
- Shows two paragraphs of text above the embedded player.
